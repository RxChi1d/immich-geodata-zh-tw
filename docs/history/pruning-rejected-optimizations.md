> **文件狀態：歷史紀錄**

更新日期：2026-09-12

## 為什麼要留這份紀錄

剪枝器的開發過程中做了兩個最佳化，都**實作完成、量測完成**，最後都沒有進主線。
刪掉程式碼會讓後人重新想到同樣的點子、重新實作、重新踩同一個坑，所以把三樣東西
留在版控裡：**錯誤的幾何命題與它的反例**、**量測結論**、**測試覆蓋的真實邊界**。

兩者都不是因為「寫壞了」被刪，而是因為**效益實測接近零，而留著會增加正確性的維護
責任**——一條平常不執行的證明路徑腐化時沒人會發現。

---

## 一、E3′ 快速路徑

### 想法

證明器把候選 p 的責任區 `Rp` 細分成 cell 逐一判定。`Vor(p)`（p 的 Voronoi cell）
是 `Rp` 內最「安全」的一塊——如果能**一次**認證整個 `Vor(p)`，細分就只需要跑剩下
的環帶，省下大量 cell。

判準：把 p 從 Delaunay 三角化中移除，對留下的洞重新三角化，若所有相關三角形的
**球面外接圓半徑**都 ≤ 25 km，則 `Vor(p)` 整塊已被覆蓋。

### 被否決的理由

實測效益是零：

| 指標 | 不開 E3′ | 開 E3′ |
|---|---|---|
| 總 cell 數 | 41,963,419 | 41,963,207 |
| 受益的候選 | — | 22 / 193,541 |
| 時間 | 101 s | 102 s |

4196 萬個 cell 只省下 212 個。原因是 `Vor(p)` 在細分器眼中本來就便宜——它靠近 p，
第一層或第二層就解掉了；貴的是外圈環帶，而 E3′ 一格都沒幫上。

### **最重要的一件事：第一版的判準是不健全的**

第一版只檢查**補洞後的新三角形**，隱含假設「`Rp` ⊆ 補洞後的三角形聯集」。

**這個假設是錯的。** 當某個 p-incident 三角形在 p 處是鈍角時，`Rp` 會超出洞的範圍。

反例（平面座標，投影到球面上的小尺度版本即可重現）：

```
p = (0, 0)      a = (0.5,  1)
d = (-0.5, 0)   b = (0.5, -1)

洞三角形 abd 的外接半徑  = 1.00 單位
舊三角形 pab 的外接半徑  = 1.25 單位   ← 更大
```

只看洞三角形會得到 1.0，但 `Vor(p)` 的頂點實際需要 1.25。**判準必須同時檢查舊的
p-incident 三角形與新的洞三角形，取兩者的最大值。**

當時釘住這個反例的單元測試原碼（`src/pipeline/prune/e3.rs`）：

```rust
#[test]
fn the_counterexample_that_broke_the_first_criterion() {
    // p=(0,0) a=(0.5,1) b=(0.5,-1) d=(-0.5,0) 投影到球面上的小尺度版本。
    // 只看洞三角形 abd 會得到 R≈1，但 Vor(p) 的頂點需要 1.25——舊三角形 pab
    // 的外接半徑。判準必須同時看 R_old。
    let k = 1e-6_f64;
    let pt = |x: f64, y: f64| normalize(&[1.0, k * x, k * y]);
    let (pa, pb, pd) = (pt(0.5, 1.0), pt(0.5, -1.0), pt(-0.5, 0.0));
    let pp = pt(0.0, 0.0);
    let r_hole = spherical_circumradius(&pa, &pb, &pd).expect("不應退化");
    let r_old = spherical_circumradius(&pp, &pa, &pb).expect("不應退化");
    let unit = R_EARTH * k;
    assert!((r_hole / unit - 1.0).abs() < 1e-3, "洞三角形半徑應為 1 單位");
    assert!((r_old / unit - 1.25).abs() < 1e-3, "舊三角形半徑應為 1.25 單位");
    assert!(r_old > r_hole, "舊三角形較大——只看洞會低估，這正是反例");
}
```

**任何未來想做類似最佳化的人，請把這個反例接進自己的驗證。** 上面那條測試守的是
當時 `e3.rs` 裡的函式，另一條實作路徑即使重犯同一個假設，它也不會被執行到。

### 測試覆蓋的誠實邊界

用實際資料做的交叉檢查**無法**區分健全與不健全的版本：把判準改回不健全的版本，
也只多認證 5 個候選，而且那 5 個用細分器仍然證得出來。**保護來自證明本身與上面
那條釘住反例的測試，不來自資料比對。** 資料比對在這份資料上沒有辨識力。

## 二、跨趟重用證書

### 想法

剪枝是多趟執行的，每趟只刪一個獨立集。上一趟證出「可刪」但被選取規則跳過的候選，
下一趟要重證一次。若能沿用上一趟的結論，就能省下重證的成本。

證書＝該候選用到的**見證點**清單。沿用的條件是**見證點全部仍存活**。

理由：T1 證書的內容是「見證點 s 在 25 km 內蓋住這個 cell」，T2 是「保留點 r 必入盒
且嚴格近於 p」——兩者都只依賴見證點自身與 p 的座標，不受別處刪點影響；`Rp` 也只由
p 的座標與 25 km 常數決定，跨趟不變。

不必額外檢查 T0。論證：根 cell 含 p 自己，故含 p 的葉 cell 其 `dp_lo = 0`，沒有
任何 r 能滿足 `d_hi(r) < 0` → T2 單獨證不出中央 cell → 每個證出的點都在中央 cell
用了 T1 → 都滿足 T0。而刪掉 T0 鄰居 n 之後，p 的新鄰居 ⊆ N(n)，標籤仍與 p 相同，
T0 不會由真變假。

### 量測（JP + ID 全量，20 趟）

| 模式 | 刪除數 | 輸出 sha256 | 時間 |
|---|---|---|---|
| 不重用 | 158,322 | `c7d88bda…` | 57.9 s |
| 重用＋重證並斷言一致 | 158,322 | `c7d88bda…`（相同） | — |
| 重用 | 158,320 | `bbe7dd14…`（**不同**） | 53.3 s |

可重用比例：pass 2 為 57.0%，隨趟數遞減至 pass 20 的 31.4%。

### 被否決的理由

**主要理由：開啟後會改變產出。** 這是唯一一個會讓同一份輸入產生不同輸出的選項。

機制：跨趟重挑見證點時會挑到**另一組同樣合法**的見證點（每趟 0–3 筆不同）。見證點
會餵給選取階段的 pin，pin 改變就改變獨立集的選取結果。逐趟有時多刪有時少刪，
淨 −2 筆（0.001%）。**兩邊都是合法答案**，但不重用的那個才是與 Python 原型逐趟
對得上的輸出。事前訂的驗收條件是「與重證逐位元相同」，重用沒有通過。

**次要理由：只省 4.6 s（8%），遠低於預期。** 結構性原因：重用只跳過**證出**的候選，
那是便宜的（中位數約 21 個 cell）；貴的尾巴是**證不出**的候選，會用滿預算，而證不出
就沒有證書可以重用。**可重用的集合與成本反相關。**

### Soundness 的結論

重用本身是**健全的**。「重用並重證」模式跑滿 20 趟、約 30 萬次沿用，「沿用說可證
但重證失敗」的斷言**零觸發**。健全性來自上面那段論證，這次跑是確認，不是證明。

### 測試覆蓋的誠實邊界

當時加的整合測試經突變測試證實**測不到見證點存活檢查**——把存活檢查拿掉，測試仍然
綠燈，因為那個均勻網格 fixture 太規律，違規沿用剛好也都是對的。**存活檢查的證據是
全量資料的跑，不是那條測試。**
