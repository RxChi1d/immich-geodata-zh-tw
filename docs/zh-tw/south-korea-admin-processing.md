## 2026 年行政區改制

`HangJeongDong_ver20260701` 反映 2026-07-01 生效的兩項法定改制。兩者都是本專案必須追隨的行政區變更，而非資料錯誤。

### 全南光州統合特別市

依「전남광주통합특별시 설치를 위한 특별법」（법률 제21446호，2026-03-05 公布、2026-07-01 施行），廢止전라남도與광주광역시，設立전남광주통합특별시，地位比照首爾特別市。

- 下轄 27 個基礎自治團體：5 市（목포·여수·순천·나주·광양）、原光州 5 區（동·서·남·북·광산）、17 郡
- 影響 393 筆，行政代碼整批重編（`46110`／`29110` → `12110`）
- 本專案輸出為「全南光州市」——依 Admin 1 對照表既有慣例去除行政類別修飾詞，而非官方漢字全稱「全南光州統合特別市」

### 仁川廣域市改區

依「인천광역시 제물포구ㆍ영종구 및 검단구 설치 등에 관한 법률」（법률 제20161호，2024-01-30 公布、2026-07-01 施行）與「인천광역시 서구 명칭 변경에 관한 법률」（법률 제21734호）：

| 改制前 | 改制後 |
| :--- | :--- |
| 중구（內陸）＋ 동구 | 제물포구（濟物浦區） |
| 중구（영종도一帶） | 영종구（永宗區） |
| 서구（北部，以경인 아라뱃길為界） | 검단구（黔丹區） |
| 서구（其餘） | 서해구（西海區） |

仁川由 2 郡 8 區變為 2 郡 9 區。

## 行政區層級說明

> [!NOTE]
> `admin_3` 與 `admin_4` 只存在於本專案的中介 CSV，用於保留來源行政層級供追溯與除錯，不會輸出到 Immich 使用的 cities500。Immich 顯示的最細層級是 `admin_2`。代表點密度取決於 extract 的來源 feature 顆粒度（南韓為行政洞），與這兩個欄位無關。


南韓採用三級行政區系統（不包含國家層級）：

| 層級 | 韓文名稱 | 類型 | 數量 | 對應欄位 |
|------|----------|------|------|----------|
| **Admin 1** | 廣域市／道／統合特別市 | 광역자치단체 | 16 個 | `sidonm` |
| **Admin 2** | 市/區/郡 | 기초자치단체 | 253 個（譯名 235 種） | `sggnm` |
| **Admin 3** | 洞/邑/面 | 행정동/법정동 | 3,534 筆（名稱 2,802 種） | 解析自 `adm_nm` |
| **Admin 4** | 原始 Admin 3 | - | 僅市區拆分時（492 筆） | 保留原始資料用 |

> **統計基準**：以 `HangJeongDong_ver20260701` 圖資產生的 `data/handler/kr_geodata.csv`（共 3,558 筆）為準。

> **說明**：Admin 4 僅在市區拆分時使用（如「성남시분당구」拆分為「성남시」+「분당구」），用於保留原始 Admin 3 資料。此欄位對 Immich 反向地理解析無作用，僅供資料完整性與除錯使用。

### Admin 1 分類統計

16 個一級行政區包含以下類型：

- **特別市**（특별시）：1 個 - 首爾
- **廣域市**（광역시）：5 個 - 釜山、大邱、仁川、大田、蔚山
- **統合特別市**（통합특별시）：1 個 - 全南光州
- **特別自治市**（특별자치시）：1 個 - 世宗
- **道**（도）：5 個 - 京畿道、忠清北道、忠清南道、慶尚北道、慶尚南道
- **特別自治道**（특별자치도）：3 個 - 江原特別自治道、全北特別自治道、濟州特別自治道

> [!NOTE]
> 2026-07-01 起，전라남도與광주광역시依「전남광주통합특별시 설치를 위한 특별법」（법률 제21446호）合併為전남광주통합특별시，一級行政區由 17 個減為 16 個。詳見[2026 年行政區改制](#2026-年行政區改制)。

### Admin 2 類型

基礎自治團體（기초자치단체）主要分為：

- **市**（시）：主要城市地區
- **區**（구）：廣域市下的行政區
- **郡**（군）：農村地區

### Admin 3 類型

- **洞**（동）：城市地區的基層行政單位
- **邑**（읍）：城鎮地區
- **面**（면）：農村地區

## 廣域市/道類型介紹

南韓的 16 個一級行政區採用不同的命名規則，在翻譯時需考慮臺灣使用者的習慣：

### 命名規則

1. **特別市／廣域市／特別自治市／統合特別市**：統一輸出為「X市」
   - 範例：서울특별시 → 首爾市、부산광역시 → 釜山市、세종특별자치시 → 世宗市、전남광주통합특별시 → 全南光州市

2. **道／特別自治道**：統一輸出為「X道」，特別自治道去除「特別自治」修飾詞
   - 範例：경기도 → 京畿道、강원특별자치도 → 江原道、전북특별자치도 → 全羅北道、제주특별자치도 → 濟州道

兩條規則其實是同一條：**去除行政類別修飾詞（特別／廣域／特別自治／統合特別），
只保留地名 + 市／道**。市級與道級套用同一套邏輯，Immich 的地點欄位才不會出現
「首爾市／全北特別自治道」這種一半簡稱、一半全稱的組合。

### 為什麼不使用改制後的官方全稱

南韓近年將數個道改制為特別自治道（제주 2006、강원 2023、전북 2024），官方全稱
因此變成「江原特別自治道」「全北特別自治道」。本專案仍輸出改制前的傳統道名，
依據如下：

- **繁中媒體通用傳統道名。** 雄獅旅遊、KKday 台灣站、聯合新聞網一致使用「江原道」
  「全羅北道」；官方全稱在繁中語境幾乎只見於日文來源與韓方的日文版官網。
- **與市級規則一致。** 沒有人寫「首爾特別市」，同理也不寫「江原特別自治道」。
- **顯示長度。** Immich 的地點欄位並排顯示各層級，全稱會讓道級明顯長於市級。

> **注意**：國家教育研究院樂詞網未收錄這三個道，因此這是**使用慣例**而非官方譯名
> 裁決。若國教院日後收錄並採用官方全稱，此規則需重新評估。

## 中心點計算方法

### 挑戰與解決方案

南韓橫跨 UTM 51N 和 52N（東經 124°～132°），固定 UTM 區會導致邊界行政區產生嚴重誤差。

**採用動態 UTM 區選擇結合 Albers 投影**：

1. **Albers 等面積投影**：計算多邊形的準確幾何中心點經度（參數 `lat_1=33`、`lat_2=43`、`lat_0=37`、`lon_0=127.5`）
2. **動態 UTM 區判定**：根據中心點經度選擇適當的 UTM 區（51N 或 52N）
3. **UTM 投影計算**：在各自的 UTM 區中計算最終中心點座標
4. **投影轉換快取**：逐 feature 計算，同一 UTM 區的投影轉換物件快取重用；feature 數達 10,000 以上才啟用多執行緒，南韓 3,558 筆為單執行緒

## 繁體中文翻譯策略

### 翻譯層級與優先順序

南韓地理資料的翻譯採用分層策略，平衡翻譯品質與 API 請求效率：

| 層級 | 翻譯方法 | 數量 | Wikidata 查詢 |
|------|----------|------|----------|
| **Admin 1** | 內建對照表 + Wikidata QID | 16 | 16 個項目 |
| **Admin 2** | Wikidata 定位實體 + 韓文維基漢字 | 229 | 229 個項目 |
| **Admin 2（世宗市）** | **手動對照表** | 24 | **無** |
| **Admin 3** | 保留韓文原文 | 3,534 | 無 |

> [!NOTE]
> 「查詢項目數」不等於 HTTP 請求數：每個未命中快取的項目各送出一次實體搜尋，標籤以每批 32 筆取回，另對候選實體送出 P131 驗證查詢。快取完整命中時不發出任何請求。

> [!NOTE]
> 世宗特別自治市的 Admin 2 採用手動對照表，完全跳過 Wikidata 查詢。詳細原因見[世宗市手動對照表](#2-手動對照表翻譯)。

**設計理由**：

1. **Admin 1**：使用內建對照表提供臺灣慣用的簡潔名稱（如「首爾市」而非「首爾特別市」），但仍取得 QID 供 Admin 2 驗證
2. **Admin 2**：由 Wikidata 負責「認出是哪個實體」，名稱本身取自韓文維基的漢字表記（見[Admin 2 名稱來源](#admin-2-名稱來源韓文漢字)），數量適中（229 個）
3. **Admin 2（世宗市）**：使用手動對照表，確保 100% 繁體中文覆蓋率
4. **Admin 3**：保留韓文原文，避免 3,500+ 次 API 請求，且對使用者體驗影響較小

使用**內建對照表**提供臺灣慣用名稱（非 Wikidata 官方名稱），涵蓋全部 16 個一級行政區。表中另保留改制前的 `광주광역시` 與 `전라남도` 兩條，供舊版圖資重跑使用。完整對照表位於 `src/pipeline/extract/handlers.rs`：

| 부산광역시 | 釜山市 | 충청북도 | 忠清北道 |
| 대구광역시 | 大邱市 | 충청남도 | 忠清南道 |
| 인천광역시 | 仁川市 | 전북특별자치도 | 全羅北道 |

### Rust Wikidata 翻譯來源與快取

Rust production handler 會使用通用 Wikidata translation cache pipeline 讀取並更新本地
`geoname_data/KR_wikidata_cache.json`。若 cache 不存在或缺少翻譯項目，production
extract 會查詢 Wikidata、補齊 context-aware cache，再套用內建 Admin 1 與世宗對照表，
最後以韓文維基的漢字表記覆寫 Admin 2 名稱（見下節）。
自動化 fixture 驗證仍使用指定的 `KR_wikidata_stub.json`，不呼叫即時 Wikidata 網路服務，
避免 release gate 受到 API quota、上游資料漂移或網路狀態影響。

若需要更新南韓翻譯來源，使用真實 KR GeoJSON 重新執行 production extract 即可更新
cache；fixture 或 parity 驗證若需要固定輸出，仍應使用對應的 stub/cache。

### Admin 2 名稱來源：韓文漢字

Admin 2 的中文名稱**取自韓文維基百科條目的漢字表記**，不使用 Wikidata 的中文標籤。

韓國行政區名本來就是漢字詞，漢字是**原文**而非翻譯——這與日本 handler 直接沿用圖資中的日文漢字是同一個原則。Wikidata 的中文標籤則是二手產物，實測有三類系統性錯誤：

| 錯誤類型 | 實例 | 成因 |
| :--- | :--- | :--- |
| 誤抓機關名稱 | `관악구` 的 `zh-hant` 為「冠嶽區**廳**」 | 機器人從中文維基 infobox 的 `governing_body` 欄位匯入，抓到的是區公所而非行政區 |
| 簡繁轉換選錯字 | `함평군` → 「**鹹**平郡」（應為咸平郡）、`관악구` → 「冠**嶽**區」（應為冠岳區） | `zh-tw`／`zh-hk` 標籤由 `zh` 經簡繁轉換批次產生，踩到一對多映射 |
| 行政層級變更未更新 | `여주시` → 「驪州**郡**」（2013 已升格為市）、`검단구` → 「黔丹**面**」（2026 已設區） | 上游標籤未隨改制更新 |

改以漢字為準可一次消除這三類，且**不需維護任何人工對照表**。

**流程**：

1. Wikidata 負責「認出是哪個實體」——搜尋、候選過濾、P131 隸屬驗證。
2. 取該實體的 `kowiki` sitelink，抓取條目開頭純文字。
3. 從首句括號中抽出漢字，如 `함평군(咸平郡)은 …` → `咸平郡`。
4. 漢字若缺行政層級後綴則補回（시→市、군→郡、구→區）。少數條目以不含層級的名稱起首，如 목포시 的首句是 `목포(木浦, Mokpo)`，補為 `木浦市`。
5. 抽不到漢字時保留 Wikidata 標籤，不使結果變差。

抽出的漢字寫入快取的 `labels[<QID>].kohanja`，重跑時不再連線韓文維基。

> [!NOTE]
> 韓國漢字使用康熙字典舊字形，與臺灣標準字體不同——如 `淸州市`（非清）、`尙州市`（非尚）、`鎭川郡`（非鎮）、`靑陽郡`（非青）、`鷄龍市`（非雞）。此處**刻意保留來源國字形**，與日本資料保留 `県`、`沢`、`塩`、`浜` 等日式新字體的處理方式一致。

**Wikidata 標籤回退鏈**（僅在抽不到漢字時使用）：

1. zh-TW（繁體中文-臺灣）
2. zh-Hant（繁體中文）
3. zh（簡體中文，透過 OpenCC 轉繁體）
4. en（英文）
5. ko（韓文標籤）
6. 中文維基百科條目標題（經繁化）
7. 韓文原名（所有來源皆失敗）

> [!NOTE]
> 第 4、5 步命中的英文或韓文標籤，會被 `is_valid_chinese_translation` 擋下並回退韓文原名，因此不會成為輸出。現行 `geoname_data/KR_wikidata_cache.json` 的 245 筆翻譯中，229 筆 Admin 2 全部由漢字提供（`kowiki-hanja`），其餘 16 筆為 Admin 1（實際輸出走內建對照表）。

#### 候選過濾配置

翻譯 Admin 1 與 Admin 2 時，**候選實體的韓文標籤必須與查詢名稱完全相同**，否則不列入候選。

**設計理由**：

先前的作法是排除含「의회」「구청」「교육청」「廳」「government」等關鍵字的候選，但這套黑名單有兩個致命問題：

- **會誤殺正確候選**。它檢查候選的*所有語言*標籤，任一語言含關鍵字就整個剔除。`관악구`（`zh-hant` 被誤填為「冠嶽區廳」）與 `송파구`（「鬆坡區廳」）因此雙雙落選，改選到區內的洞（신림동）與地鐵站（잠실역），已發布資料中共 48 筆地名因此錯誤。
- **永遠列不完**。實測搜尋「전남광주통합특별시」的七個候選裡，教育監（교육감）、選舉管理委員會（선거관리위원회）、市內公車（시내버스）都不在黑名單上。

改用韓文標籤全等比對後，機關、職位、選區、車站全部自然落選，且對現行 245 筆實測零誤判。

> [!IMPORTANT]
> 此過濾器**必須同時套用於 Admin 1**。2026 年改制後搜尋「전남광주통합특별시」時，同名的教育廳（`…교육청`）其 P131 鏈同樣可回溯至大韓民國、能通過隸屬驗證；若 Admin 1 未過濾，會取到機關實體，再讓其下 27 個行政區的 parent QID 全部指錯。

> [!NOTE]
> 世宗特別自治市的 Admin 2 完全使用手動對照表，不經過 Wikidata 流程，因此不使用此過濾器，也不套用漢字覆寫。

#### 隸屬驗證缺漏時直接失敗

Admin 2 的 P131 隸屬驗證需要其 Admin 1 的 QID。**任何 Admin 1 解析不出 QID 時，extract 直接報錯中止**，不會沿用共用層「退回國家 QID」的預設行為。

共用層的預設行為對 Admin 2 太寬鬆——以國家 QID 驗證等於把「這個 동구 是不是這個市底下的」放寬成「這個 동구 在不在韓國」，釜山東區、大邱東區全都會通過。2026 年改制時正是這條靜默降級，把單一 Admin 1 查錯放大成 393 + 27 筆錯誤輸出，而且過程中沒有任何錯誤訊息。

改為直接失敗後，下次改制會在 extract 階段當場停住，而不是安靜地把錯誤資料送進發布流程。

## 資料正規化

本章節說明南韓地理資料的通用正規化處理，適用於全國大部分地區。

### 市區合併名稱拆分

部分城市在 `sggnm` 欄位中採用合併寫法「`<市名>시<區名>구`」（例如「성남시분당구」），造成兩個問題：

1. **翻譯困難**：Wikidata 條目為單獨區名（`분당구`），合併名稱查詢失敗
2. **顯示混亂**：Immich 將市區合併名稱與洞/邑/面放在同一層級

**處理邏輯**：

1. **偵測**：名稱以 `구` 或 `군` 結尾時，從第一個 `시` 之後切開為市名與區／郡名（實作見 `src/pipeline/extract/handlers.rs` 的 `split_korea_city_district`）
2. **拆分**：
   - `sggnm` → 市級名稱（`성남시`）
   - `admin_3` → 區/郡名稱（`분당구`）
   - `admin_4` → 原始 Admin 3（`태평3동`）

**效果**：
- Admin 2 得以對應到市級名稱，提升 Wikidata 匹配率
- 層級結構：京畿道 → 城南市（admin_2，已翻譯）→ 분당구（admin_3，保留韓文）→ 태평3동（admin_4，原始資料）
- 原始資料保留於 `admin_4`

### 同名地名處理

南韓有多個重複的行政區名稱，需要透過 P131 驗證確保選擇正確實體。

#### Admin 2 層級

6 個重複名稱，但在各自 Admin 1 下唯一：

| 名稱 | 出現次數 | 所屬 Admin 1 |
|------|----------|------|
| 중구（中區） | 5 | 首爾市、釜山市、大邱市、大田市、蔚山市 |
| 동구（東區） | 5 | 釜山市、大邱市、大田市、蔚山市、全南光州市 |
| 서구（西區） | 4 | 釜山市、大邱市、大田市、全南光州市 |
| 남구（南區） | 4 | 釜山市、大邱市、蔚山市、全南光州市 |
| 북구（北區） | 4 | 釜山市、大邱市、蔚山市、全南光州市 |
| 강서구（江西區） | 2 | 首爾市、釜山市 |

> **註**：고성군 在兩處的譯名不同（江原道為高城郡、慶尚南道為固城郡），因此在中文層並不同名。仁川的중구／동구／서구已於 2026-07-01 改制為제물포구／영종구／서해구／검단구，不再參與同名情形。

**處理**：透過 P131 驗證確保選擇正確 Admin 2（例如「中區」必須位於「首爾」之內）。

#### Admin 3 層級

約 229 個重複名稱（以 `HangJeongDong_ver20260701` 圖資統計），不影響 Immich 顯示（通常僅顯示至 Admin 2）。

**策略**：保留韓文原文，不翻譯。

### 消歧義括號處理

部分地名在 Wikidata 中帶有消歧義括號（如「東區 (光州)」），但在本專案的資料結構中，`admin_1` 已經標明父級地區，因此 `admin_2` 不需要重複標註。

**處理邏輯**：

Rust handler 對**所有** Admin 2 記錄移除結尾的消歧義括號，實作為 `src/pipeline/extract/handlers.rs` 呼叫的 `strip_trailing_parenthetical`。

原先此規則僅限 `sidonm == "광주광역시"` 時套用。2026-07-01 光州併入전남광주통합특별시後，該條件永不成立、剝除**靜默失效**，`東區 (光州)` 會原樣輸出且不會有任何錯誤訊息。這種「改制即失效」的白名單不應再出現，故改為一律套用——韓國行政區的正式中文名不含括號，無誤傷風險。

改用韓文漢字作為名稱來源後，這條規則在主要路徑上已不會被觸發（漢字沒有消歧後綴），但仍保留給 Wikidata 標籤回退鏈使用。

**護欄**：`strip_trailing_parenthetical` 只認「尾端閉括號 + 最後一個同型左括號」，對巢狀或不成對的括號會切出壞字串。因此剝除結果為空、或仍殘留括號時，一律保留原值：

| 輸入 | 輸出 | 理由 |
| :--- | :--- | :--- |
| `東區 (光州)` | `東區` | 正常剝除 |
| `甲（乙（丙））` | `甲（乙（丙））` | 剝除會留下未閉合的 `甲（乙` |
| `（甲）` | `（甲）` | 剝除後為空字串，等同地名遺失 |

## 世宗特別自治市特殊處理

世宗特別自治市（세종특별자치시）是南韓唯一的**單層級特別自治市**，行政結構與其他廣域市不同，需要專門的處理流程。此處理方式可作為其他國家類似結構的參考。

**結構差異**：

```
標準結構：廣域市/道 → 市/區/郡 → 洞/邑/面
世宗結構：世宗特別自治市 → 洞/邑/面 ← 沒有中間層級！
```

### 資料問題

原始 GeoJSON 的 `sggnm` 欄位（Admin 2）對世宗一律填入 `세종시`，早期版本則填入政府機構名稱：

- `세종특별자치시광역자치의회`（議會）
- `세종특별자치시청`（市廳）

兩者都不是真實的 Admin 2；若直接使用會導致 Immich 顯示「世宗 > 世宗市」或「世宗 > 議會」，而非「世宗 > 鳥致院邑」。

### 處理方式

本專案採用**兩階段處理機制**解決世宗的特殊結構與翻譯問題：

#### 1. 行政層級正規化

將世宗記錄的洞/邑/面從 Admin 3 提升至 Admin 2，符合其單層級結構：

- **檢測條件**：`sggnm` 不以읍/면/동結尾（排除真實行政區）
- **正規化動作**：Admin 3 → Admin 2，清空 Admin 3

**範例**：
```
處理前：세종특별자치시 → 세종시 → 대평동
處理後：세종특별자치시 → 대평동 → (空)
```

#### 2. 手動對照表翻譯

**問題**：世宗市於 2012 年成立，多數新設洞在 Wikidata 缺少中文標籤，早期實作因而回退至羅馬拼音（`Boram-dong`）甚至韓文原文。

**解決方案**：Rust handler 內建 25 筆手動對照表（`src/pipeline/extract/handlers.rs` 中的 `sejong_admin2`），涵蓋現行圖資全部 24 個 Admin 2 地名，另含尚未出現於現行圖資的 `합강동`（合江洞）。

**對照表範例**：

| 韓文 | 繁體中文 |
|------|----------|
| 보람동 | 寶藍洞 |
| 대평동 | 大平洞 |
| 다정동 | 多情洞 |
| 도담동 | 陶潭洞 |
| 고운동 | 高雲洞 |
| 조치원읍 | 鳥致院邑 |
| 부강면 | 芙江面 |
| 장군면 | 將軍面 |

**翻譯流程**：

```
1. 檢測世宗特別自治市 → 2. 查詢對照表 → 3. 返回繁體中文
                                           （跳過 Wikidata）
範例：보람동 → 寶藍洞
```

**成果對比**：

| 原始韓文 | Wikidata 翻譯 | 手動對照表 |
|---------|--------------|-----------|
| 보람동 | Boram-dong ❌ | 寶藍洞 ✅ |
| 대평동 | Daepyeong-dong ❌ | 大平洞 ✅ |
| 어진동 | 어진동 ❌ | 汝珍洞 ✅ |
| 조치원읍 | 鳥致院邑 ✅ | 鳥致院邑 ✅ |

> [!NOTE]
> 「Wikidata 翻譯」欄呈現的是導入手動對照表前的歷史行為。現行 Rust 實作以 `is_valid_chinese_translation` 擋下羅馬拼音與中英夾雜的結果並回退韓文原名，且世宗根本不進入 Wikidata 流程。

> [!NOTE]
> 經過兩階段處理後，世宗記錄的 Admin 2 會顯示洞/邑/面的繁體中文名稱（如「鳥致院邑」、「燕岐面」、「寶藍洞」），Admin 3 保持空白。這樣 Immich 就能正確顯示「世宗 > 鳥致院邑」等地理資訊。
