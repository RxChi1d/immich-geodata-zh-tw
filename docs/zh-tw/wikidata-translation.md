# Wikidata 譯名的已知失效形態

南韓、泰國與印尼 handler 以 Wikidata 取得行政區的繁體中文名稱。本文記錄實際
遇過的失效形態、判別方式，以及現行程式碼的防線範圍。新增使用 Wikidata 的國家
或更新既有國家的圖資時，請先讀過本文。

## 失敗是無聲的

查不到實體、選到錯誤實體或隸屬驗證不通過時，handler 一律回退為來源原文，不會
報錯。錯誤譯名同樣不會報錯——它們是合法的中文字串，只是指向錯的地方。

因此驗證資料時**必須比對未翻譯名稱的完整清單，不能只看總數**。一個地名掉出、
另一個地名首次翻譯成功時，總數不會變。實際案例：印尼從舊版換到新版圖資時，未
翻譯的 `admin_2` 名稱數維持 51 個，逐筆比對才發現 `Kabupaten Ngawi` 掉了、另一
個地名補上。

## 六種形態

以下為 2026 年 8 月的觀察。部分案例已回報並修正上游，因此照著「判別方式」重查
時未必仍能重現。

| 形態 | 案例 | 判別方式 |
| :--- | :--- | :--- |
| 搜尋選到錯誤實體（下級行政區、設施或機關） | 首爾 `관악구` 選到區內的 `신림동`；`송파구` 選到地鐵站 `잠실역`；`전남광주통합특별시` 選到同名的教育廳，導致 27 個下級行政區的 parent QID 全部指錯 | 候選的原文 label 與查詢名稱不相等 |
| 上游 label 停在舊制 | `여주시` 的中文 label 曾是 2013 年升格前的「驪州郡」；`검단구` 曾停在設區前的「黔丹面」 | 行政層級後綴與原文對不上（시→市、군→郡、구→區） |
| 簡繁轉換選錯字 | `함평군` 的 `zh-tw` label 曾把「咸」轉成「鹹」；印尼 Papua 的 `zh-hant` 曾殘留簡體「巴布亚」 | 人工抽查，或以簡體字白名單掃描 |
| 缺少 `P131` 敘述 | `영종구` 設區後一段時間內完全沒有 | 隸屬驗證失敗且查無敘述 |
| `P131` 被標為 deprecated | 印尼 `Kabupaten Ngawi` 隸屬東爪哇省的敘述曾被標 deprecated | SPARQL 的 `wdt:` 前綴只走 best-rank statement，deprecated 等同不存在 |
| 我方過濾規則誤殺正確候選 | 關鍵字黑名單檢查候選的**所有語言** label，正確的 `관악구` 因 `zh-hant` 被機器人填成「冠嶽區廳」含「廳」字而被剔除 | 正確實體不在候選結果中 |

最後一種不是上游問題，是防護機制反噬。黑名單式的排除規則永遠列不完，而且會因為
某個無關語言的 label 誤傷正確候選。改用白名單式判定——原文 label 必須與查詢名稱
完全相符——機關、職位、選區、車站會自然落選。

## 現行防線與其範圍

這些防線多數是各國 handler 各自實作，共用層並未一體套用。新增國家時不能假設
已受保護。

| 防線 | 實作位置 | 適用範圍 |
| :--- | :--- | :--- |
| 候選過濾 | 各國自行提供 `candidate_filter` | KR 為韓文 label 全等比對（admin1 與 admin2 皆套用）；TH／ID 各有自己的排除規則 |
| parent QID 缺一即報錯 | `korea_admin2_parent_qids` | **僅 KR**。共用層的 `resolve_parent_qid` 仍會在查無 parent 時回退國家 QID，TH／ID 建表時則直接略過缺漏項目 |
| 行政層級後綴一致性 | `korea_admin2_level_matches` | **僅 KR admin2**。不符時回退韓文原名，會出現在輸出 CSV 的未翻譯清單中 |
| 簡體字偵測 | `WikidataTranslator::warn_if_simplified` | 共用層，但**只告警不改寫**——共用層自動簡轉繁會波及既有正確輸出 |
| 簡體字轉換 | `indonesia_normalize::fix_simplified_chars` | **僅 ID**。使用 `src/wikidata/simplified.rs` 的白名單，只轉換簡體獨有、無正體歧義的字 |

簡體字為何不用完整 OpenCC s2t：實測對真實印尼輸出套用完整 s2t 會改壞 24 個正確
譯名（`里→裏`、`占→佔` 等過度轉換），只修好 1 個。白名單只犧牲涵蓋率，不製造
新錯誤。

## 優先修正上游

某個譯名錯誤若源自 Wikidata 本身，**優先修正 Wikidata，而不是在本專案加對照表**。
修正上游對所有使用者都有效；對照表只對本專案有效，且需要長期維護。

南韓 handler 的實例：原本規劃七條人工對照表，改用韓文維基的漢字表記作為 admin2
名稱來源後降為零條——韓國行政區名本來就是漢字詞，漢字是原文而非翻譯，與日本
handler 沿用圖資中的日文漢字同一原則。

## 快取

`geoname_data/{國碼}_wikidata_cache.json` 分為多層：`cache.search`、`cache.labels`、
`cache.instance_of`、`cache.p131` 存各階段的查詢結果，`translations` 存最終譯名決策
（key 格式 `<層級>/<國碼>/<上層行政區…>/<原名>`）。

`translations` 命中且上層行政區脈絡未變時會直接採用，不再查 `cache.p131`。因此
**只清 `cache.p131` 不會有任何效果**。

- 修正上游單一實體後要重驗：該實體的 `cache.p131` 與 `translations` 兩處都要清。
- 修改候選篩選邏輯，或修改過上游 label：直接以空快取重跑。篩選邏輯還會吃
  `cache.search` 與 `cache.labels`，選擇性清除容易漏。
