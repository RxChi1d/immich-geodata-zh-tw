# 地名點剪枝

> 本文件說明 release pipeline 中的 **prune** 階段：它如何在不改變任何查詢結果的
> 前提下，刪掉三分之一的地名點。這一步位於 translate 之後、pack 之前，
> **不限國別**——候選資格純粹由資料決定，不靠國家清單。

## 1. 問題

Immich 匯入的 `cities500.txt` 逐年變大。本專案改用官方圖資重建地名後，點的密度
遠高於 GeoNames 原始資料——日本 125,130 點、印尼 108,673 點，兩國就佔了全球
487,372 點的將近一半。

檔案變大影響三個地方，而且**下載體積不是最重要的那個**：

| 維度 | 為什麼重要 |
| :--- | :--- |
| 解壓後的 `cities500.txt` | Immich 實際讀取與匯入的檔案 |
| `geodata_places` 表與索引 | 佔用資料庫空間，且決定每次查詢要掃幾列 |
| 反向查詢延遲 | 每張有 GPS 的相片都要查一次 |
| `release.tar.gz` | 只影響下載，且被刪的列重複度最高，壓縮本來就壓掉了 |

密集區的問題特別明顯：日本平均每次查詢要在 25 公里範圍內掃 242 列，才決定一個
地名。這些列裡有大量是**同一個行政區的不同代表點**——它們彼此競爭，但不論誰贏，
回傳的行政區名稱都一樣。

**剪枝要做的就是刪掉這種點：刪了之後，任何 GPS 座標查出來的答案都不變。**

## 2. 前提：Immich 怎麼查地點

所有設計都建立在 Immich 實際使用的查詢上（`server/src/repositories/map.repository.ts`）：

```sql
SELECT * FROM geodata_places
WHERE earth_box(ll_to_earth_public($1, $2), 25000) @> ll_to_earth_public(latitude, longitude)
ORDER BY earth_distance(ll_to_earth_public($4, $5), ll_to_earth_public(latitude, longitude))
LIMIT 1
```

回傳 `{country, state: admin1Name, city: name}`。查不到任何點時，Immich 退回
Natural Earth 的國界資料，`state` 與 `city` 為 `null`。

### 2.1 `earth_box` 是立方體，不是圓

這是整套設計最容易誤解、也最關鍵的一點。

`earth_box(p, 25000)` 產生的是**地心直角座標系中的軸對齊立方體**，半邊長
`h = 24,999.98 公尺`。它不是以 25 公里為半徑的球面圓盤。而且 `WHERE` 之後
**沒有再用 `earth_distance` 過濾**——盒子決定誰有資格參賽，`ORDER BY` 只在
參賽者之間排序。

後果是：**較近的點可能在盒外，較遠的點可能在盒內。**

![立方體與圓盤的差異：切向 20×20 公里的點距離 28.3 公里仍在盒內，軸向 25.5 公里的點在盒外](../image/pruning-box-vs-disc.svg)

*切向偏移 (20, 20) 公里的點距離 28,284 公尺，超過 25 公里但仍在盒內；正北 25.5 公里的點反而在盒外。已在 PostgreSQL 實測確認。*

所以「刪掉 p 之後最近鄰還是同一個行政區」**推不出**「SQL 的答案不變」。任何
基於純最近鄰的推論都必須另外處理盒的形狀。

### 2.2 25 公里引理

盒與圓盤的關係不是全然無解。有一個方向是成立的：

> **若某個點與查詢位置的大圓距離 ≤ 25 公里，它必定在盒內。**

證明：大圓距離 ≤ 25 km ⟹ 弦長 ≤ 25 km ⟹ 三個地心座標分量的差各自 ≤ `h`
⟹ 落在盒內。（已用 100 萬個隨機球面樣本驗證，零例外。）

推論很有用：**只要查詢位置的最近保留點在 25 公里內，盒內就一定含有全域最近點，
此時 SQL 等同於純最近鄰。** 這把「盒語意」轉換成「最近鄰語意」，讓幾何推理變得可行。

## 3. 方法：證明不了就保留

剪枝器對每個候選點 `p`，嘗試證明一個命題：

> 刪掉 `p` 之後，**所有可能受影響的查詢位置**，SQL 回傳的行政區名稱都不變。

證不出來就保留該點。這個方向的選擇是刻意的——**漏刪只是檔案大一點，錯刪會讓
使用者看到錯的地名。**

### 3.1 受影響的區域

「可能受影響」的範圍不是 `p` 的 Voronoi cell，而是：

```
Rp = { q : p 落在 earth_box(q, 25 km) 內 }
```

即所有「有可能把 `p` 納入候選」的查詢位置。因為盒的 3D 對角線長
`h·√3 ≈ 43.3 公里`，所以 `Rp` 必定落在 `p` 周圍 43.5 公里的範圍內。

`q` 在 `Rp` 之外表示 `p` 根本不在 `q` 的盒內，不可能被選中，刪除自然不影響。

### 3.2 三個判準

證明分三層，由便宜到貴。判準之間不是替代關係——**T0 從不單獨使用**。

![T0、T1、T2 三個判準的分工](../image/pruning-three-tiers.svg)

*三個判準的分工。T1 與 T2 是逐塊區域判定的，同一個候選點的不同區域可以走不同的路。*

### 3.3 怎麼檢查「整塊區域」

`Rp` 是連續區域，裡面有無限多個查詢位置，不可能逐點檢查。做法是**遞迴細分**：

1. 先把整塊區域當一塊，用**保守的區間估計**問「這整塊都安全嗎？」
2. 答得出來就結案；答不出來就切成四塊，各自再問
3. 越切越小，區間越窄，越容易答得出來

關鍵在於「保守」：每個區間都**向外放寬**，寧可答不出來也不會答錯。這與「誤差小於
幾公尺就當作安全」的做法方向相反——向外放寬讓證明**更難**成立。

![遞迴細分：整塊、切四塊、再切四塊，未解區域逐步縮小](../image/pruning-subdivision.svg)

*遞迴細分。每個候選點有固定的細分預算，用完仍有未解區域就放棄，保留該點。*

**細分用心射投影（gnomonic）而非經緯度網格。** 心射投影把大圓映射成直線，
因此平面上的直邊矩形反投影回球面後是**測地凸**的四邊形——區域內任一點都是四個
角點的正規化凸組合，這讓「用四個角推出整塊的界」成立。經緯度矩形沒有這個性質。

每塊區域的界取兩組估計的交集：**球冠界**（把區域當成外接球冠，大區域仍有效但很鬆）
與**角點界**（利用凸組合的線性性質，小區域下幾乎精確）。只用球冠界會讓細分量爆增。

### 3.4 細分預算

預算是「每個候選點最多可以切出幾塊」。調大能證出更多點，但時間也上升。全量實測
（每個預算都跑到收斂）：

| 預算 | 刪除量 | 佔比 | 時間 | 每多刪 1000 點所需秒數 |
| ---: | ---: | ---: | ---: | ---: |
| 256 | 144,264 | 29.60% | 39 s | — |
| 512 | 153,619 | 31.52% | 43 s | 0.4 |
| 1024 | 159,031 | 32.63% | 49 s | 1.1 |
| **2048** | **163,076** | **33.46%** | **61 s** | **3.0** |
| 4096 | 165,411 | 33.94% | 79 s | 7.7 |

沒有明顯的膝點，是平滑的報酬遞減：每檔加倍，多刪的點數約砍半。採用 **2048**。

平行化之後整條曲線都很便宜——4096 也只多花 18 秒。選 2048 而非 4096 的理由不是
時間，而是**邊際收益本身**：從 2048 到 4096 只多刪 1.4% 的點，換來的體積差異量不出來。

## 4. 為什麼要跑很多趟

T0 的論證需要 `p` 的鄰居**存活**。如果 `p` 和它的鄰居同時被刪，論證就斷了。

因此單趟只能刪掉一個**獨立集**——圖上兩兩不相鄰的點集。平面三角化的獨立集大約
佔 25%，所以一趟遠遠刪不完。

![多趟獨立集刪除：每趟刪掉互不相鄰的一組點，重建圖後再刪一組](../image/pruning-multipass.svg)

*每趟都以當下的保留集合重新計算球面 Delaunay 鄰接、重新證明，再選一個獨立集。*

實際跑了 **20 趟**才收斂：

| 趟 | 候選 | 證出 | 刪除 | 累計 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 252,423 | 164,382 | 36,774 | 36,774 |
| 2 | 127,608 | 127,602 | 27,636 | 64,410 |
| … | | | | |
| 19 | 1,972 | 1,963 | 502 | 162,716 |
| 20 | 1,461 | 1,446 | 360 | 163,076 |

第 2 趟之後只重新證明「上一趟已證出但因獨立集限制被跳過」的候選。刪點只會讓保留
集合變小，覆蓋與見證都更難成立，所以上一趟證不出來的這一趟幾乎不可能變成證得出來
——跳過它們是保守的。

## 5. 驗證

**證明本身才是正確性的來源。** 但證明是人寫的程式，可能有 bug，所以另外用實測
當作抓錯的網。

### 5.1 差分測試

建兩個 PostgreSQL 資料庫（原始資料與剪枝後資料），用 Immich 的查詢原文對每個探測點
各查一次，比對回傳的 `(countryCode, admin1Name, name)`。

分成兩輪，合起來涵蓋全部 163,076 個刪除。

**第一輪：455 萬個對抗式探測點**，涵蓋日本與印尼的 158,322 個刪除。探測點刻意打在
最容易出錯的地方：

| 類別 | 數量 | 為什麼選這裡 |
| :--- | ---: | :--- |
| 被刪點自身 | 158,322 | 刪除的直接影響點 |
| 與 Delaunay 鄰居的中點 | 116,918 | 兩點勢力範圍的交界 |
| 盒面兩側 ±0.01 / 1 / 50 公尺 | 2,880,000 | **專打 2.1 節的盒 vs 圓盤問題** |
| 全球隨機 | 1,000,000 | 無偏樣本 |
| 陸地取樣 | 400,000 | 與點集獨立的參考樣本 |

```
1,067,876 個探測點的原始贏家確實被刪（真的重新裁決過）
零標籤改變、零新增空結果
```

**第二輪：179 萬個探測點**，涵蓋臺灣、南韓、泰國、馬來西亞新增的 4,754 個刪除。

之所以能分兩輪，是因為第一輪驗證過的 158,322 個刪除是最終 163,076 個刪除的
**真子集**——日本與印尼的刪除決定一個都沒變（逐項比對確認），所以第一輪的結論
繼續成立，只需要驗證新增的 4,754 個。

第二輪用一個嚴格的捷徑：某個座標的結果只可能在「它原本的贏家剛好被刪」時改變，
所以先對原始資料求出每個探測點的贏家，只有贏家落在新增刪除集合裡的才需要重算。
探測範圍是四國邊界框外擴 0.5°（大於盒對角線 43.5 公里，更遠的探測在構造上不可能
受影響），步長 0.01°（約 1.1 公里）。

```
1,794,336 個探測點，其中 42,306 個的原始贏家被刪（需重新裁決）
零標籤改變、零新增空結果
```

### 5.2 差分不是正確性的來源

有一類錯誤差分抓不到，必須說清楚：

若覆蓋判斷有 bug 而誤刪了點，後果是「某個位置的最近保留點超過 25 公里」。但盒的
對角線有 43 公里，密集區的盒內**通常還有其他同名的點**，於是回傳的名稱不變、
結果也不空——**差分全零，但證明其實是錯的**。

所以差分是網，不是證明。程式的正確性由 3.2 節的判準與其推導保證，另外以單元測試
把已知的反例配置寫死在測試裡。

## 6. 結果

實測（預算 2048、跑到收斂、PostgreSQL 17）：

| 指標 | 剪枝前 | 剪枝後 | 變化 |
| :--- | ---: | ---: | ---: |
| 列數 | 487,372 | 324,296 | **−33.5%** |
| `cities500.txt`（解壓後） | 63.9 MB | 47.8 MB | **−25.2%** |
| `geodata_places` 表＋索引 | 221 MB | 164 MB | **−25.8%** |
| GiST 空間索引 | 76 MB | 41 MB | **−46.1%** |
| 反向查詢 avg（密集區） | 3.362 ms | 1.145 ms | **−66%** |
| 反向查詢 p50（密集區） | 2.004 ms | 0.626 ms | **−69%** |
| 反向查詢 p95（密集區） | 12.207 ms | 4.098 ms | **−66%** |
| `release.tar.gz` | 21.7 MB | 19.6 MB | −9.7% |

延遲以日本、印尼、臺灣、南韓、泰國的 20,000 個隨機地點各查一次量得。
`release.tar.gz` 的降幅最小，因為壓縮本來就吃掉了大部分重複——**壓縮檔大小不是
這一步的主要指標，解壓後的體積與資料庫佔用才是**。

**不同的行政區名稱一個都沒有消失。** 剪枝只刪掉同一個行政區內多餘的代表點，
不會讓任何地名從資料中消失。

### 6.1 稀疏地區不受影響

加拿大、俄羅斯這類幅員遼闊而人口稀少的地區，有大量位置在 25 公里內本來就沒有
任何點（加拿大 88.1%、俄羅斯 76.3%），Immich 對這些位置本來就退回 Natural Earth
只顯示國名。

剪枝**不會讓這個情況變差**，原因有二：

1. 稀疏表示鄰居分屬不同行政區，T0 不成立。實測全球 203,460 個 T0 候選全部落在
   日本、印尼、臺灣、泰國、南韓、馬來西亞。
2. 就算進了候選池，T1 要求「刪除後整塊區域仍被 25 公里覆蓋」，稀疏區證不出來就
   保留。實測有 **59 個國家出現候選，但只有 6 個國家證得出任何一點**：美國 12 個
   候選、中國 70 個、巴西 116 個、俄羅斯 24 個、冰島 2 個，**全部零刪除**。
   擋下它們的是證明器本身，不是任何國家清單。

換句話說，**「刪了之後 25 公里內變成沒有點」在構造上不可能發生**。

要改善稀疏地區的定位精度只能補資料，那是另一條線的工作，與剪枝無關。

## 7. 執行

剪枝是 release 流程的一個階段，預設啟用：

```bash
cargo run --release -- release --locationiq-api-key "<api_key>" --country-code MY
```

單獨執行或跳過：

```bash
cargo run --release -- prune --output-folder ./output   # 只跑剪枝
cargo run --release -- release --pass-prune ...         # 跳過剪枝
```

全量資料約需 7 分鐘（單執行緒）。
